# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Replaces UTC hour/minute with IST shift start without timezone conversion; misses grace period edge cases where minutes > 10 check on `int(10.5)` treats 10 as not late; fails on overnight shifts. | Punch-in at 10:05 IST (04:35 UTC) with 09:30 shift produces negative/zero late minutes (-295 min) due to UTC/IST mixing. Punch-in at 09:40:01 IST with 09:30 shift yields 0 instead of 10. | Convert UTC punch-in to IST, compute elapsed seconds from shift start on the attendance date (`(dt_ist - start_dt_ist).total_seconds()`), check if `diff_sec > 600`, and calculate `int(diff_sec // 60)`. |
| 2 | `compute_overtime` (lines 44-47) | Ignores the 30-minute minimum threshold (R3); crashes on subtracting naive and aware datetimes; fails for overnight shifts where shift end is on the next calendar day. | 15 minutes of overtime returns 15 instead of 0; overnight shifts calculate ~24h overtime or raise `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Added overnight shift detection (`shift_end <= shift_start`), advancing shift end by 1 day, comparing in IST, and returning `diff_sec // 60` only when `diff_sec >= 1800` (>= 30 min), otherwise 0. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies banker's rounding (round-half-to-even) and float representation inaccuracies, violating R4 (half-up rounding). | Inputs resulting in values like 2.675 round to 2.67 instead of 2.68. | Replaced with Python `Decimal` quantize using `ROUND_HALF_UP` on total seconds divided by 3600. |
| 4 | `create_employee` (lines 77-86) | Check-then-insert race condition for `emp_code`; missing schema validation for email, shift time patterns, and differing shift times; returns `created_at` as a datetime instead of epoch ms. | Concurrent requests with duplicate `emp_code` both pass `find_one`; equal shift start/end allowed; client receives string/datetime `created_at` violating the integer epoch ms contract. | Enforced database unique index on `emp_code`, catch `DuplicateKeyError` and raise HTTP 409; validated with Pydantic; return `created_at` as integer epoch ms. |
| 5 | `list_employees` (lines 88-96) | Incorrect pagination offset (`skip = page * page_size` skips the first page); missing required ascending sort on `emp_code`; `total` ignores the department query filter; missing page size validation. | `page=1&page_size=20` returns items 21-40; `total` reports collection size instead of filtered count; `page_size > 100` accepted. | Changed skip to `(page - 1) * page_size`; added `.sort("emp_code", 1)`; set `total = count_documents(q)`; added `page_size <= 100` validation. |
| 6 | `punch_in` (lines 99-121) | Crashes on unknown employee with 500 (`emp["shift_start"]` on `None`); check-then-insert race condition on `(emp_code, date)`; naive local time used instead of UTC/IST; misses overnight shift calendar date logic (R1); accepts invalid status; returns unauthorized `id` field. | Non-existent employee returns 500 instead of 404; concurrent punch-ins allow duplicates; overnight punch-in at 01:00 IST assigned wrong calendar day; response contains `id` and datetime objects instead of epoch ms. | Return 404 if employee not found; enforce unique index on `("emp_code", "date")` and catch `DuplicateKeyError` to return 409; implement R1 attendance date logic in IST; validate status in `(PRESENT, WFH, ON_DUTY)`; remove `id`/`_id` and format `punch_in` as epoch ms. |
| 7 | `list_attendance` (lines 124-150) | Loads full collection into Python memory (`list(db.attendance_logs.find(q))`) and sorts in Python, causing OOM/timeout on 100k docs; missing secondary sort by `emp_code` asc; returns unauthorized `id` field; missing `date_from > date_to` validation. | Severe latency and memory spike on 100k records; tied dates not ordered by `emp_code`; invalid range `date_from > date_to` returns 200 with empty list instead of 422. | Use MongoDB index-backed `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`; validate `date_from <= date_to` with 422; strip `_id` and format timestamps to epoch ms. |
| 8 | `health` (lines 72-74) | Returns static `{"status": "ok"}` with HTTP 200 without checking if MongoDB is reachable. | If MongoDB is unreachable or down, `/health` still returns 200 OK instead of failing. | Execute `client.admin.command("ping")` in a try/except block; return HTTP 503 if an exception is raised. |
| 9 | Database Indexes & Startup Lifecycle (lines 22-27) | No indexes created on startup; no FastAPI lifespan or startup event to ensure database indexes exist. | Endpoints perform slow collection scans (`COLLSCAN`), and concurrency uniqueness guarantees cannot be enforced by the database. | Added FastAPI `lifespan` handler to idempotently create unique and compound indexes for both `employees` and `attendance_logs` on application startup. |
| 10 | Timestamp Storage & Truncation (lines 102, 110) | `datetime.fromtimestamp(ts/1000)` produces local naive datetimes; does not truncate instants to whole seconds per R1 before calculations and storage. | Dates shifted by local machine timezone offset; sub-second milliseconds alter late and overtime thresholds. | Explicitly truncate incoming epoch ms to whole seconds (`ts // 1000 * 1000`), convert to UTC timezone-aware datetimes for BSON storage, and format responses as integer epoch ms. |

Also note anything you looked at and decided was **not** a defect, and why:
- `emp_code` being a string rather than an ObjectId: Verified against `DATA_MODEL.md` - this is the intentional design; `emp_code` is a customer business identifier, and MongoDB's `_id` must remain internal and never appear in requests or responses.
- Calendar dates (`date`, `joined_on`) and shift times (`shift_start`, `shift_end`) stored as plain strings (`"YYYY-MM-DD"`, `"HH:MM"`): Verified against `DATA_MODEL.md` - dates and times of day are strings on purpose to avoid forcing timezones onto date-only or time-of-day values.
- Lack of authentication / authorization: Verified against `PROBLEM_STATEMENT.docx` and `openapi.yaml` - authentication is explicitly out of scope for this assignment, and `regularized_by` is accepted as free text.
